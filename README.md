The duplicate check comes after validation so that an invalid first copy cannot claim a `booking_id` and cause a valid re-sent copy to be discarded as a "duplicate", which would lose a good booking and hide the real reason. The drifting field is `promo_code`: its earliest appearance is a booking made on 2026-10-20 at 01:05 UTC, and it is present in 193 documents (values `CLUB10`, `EARLY`, or null).
